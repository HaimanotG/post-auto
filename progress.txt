[iteration 10] task_id: m1-02 (Telegram initData verification middleware)
Result: Task Complete
Summary: Created apps/api/src/middleware/telegram-init-data.ts implementing Telegram's documented Mini App initData verification algorithm: secretKey = HMAC_SHA256(key="WebAppData", data=botToken), expectedHash = hex(HMAC_SHA256(key=secretKey, data=<data-check-string>)) where the data-check-string is every non-hash param sorted alphabetically as "key=value" joined by "\n". verifyTelegramInitData(initData, botToken, options) parses the initData query string, timing-safe-compares the hash, rejects payloads whose auth_date is older than 24h (default; overridable via options.maxAgeMs/options.now for testing), and parses+returns the embedded `user` JSON field — throwing a TelegramInitDataError with a specific message (missing hash/missing auth_date/stale auth_date/missing or malformed user) on any failure. upsertTelegramUser(prisma, user) upserts by telegramUserId (BigInt) mapping Telegram's snake_case user fields (first_name/photo_url) to the Prisma User model's camelCase columns. Deliberately typed against a narrow structural TelegramUserStore interface (just `{ user: { upsert(...): Promise<User> } }`) rather than `Pick<PrismaClient, "user">`, so unit tests can pass a plain `{ user: { upsert: vi.fn() } }` mock instead of implementing every UserDelegate method Prisma's generated type requires. createTelegramInitDataPreHandler(prisma, botToken) returns a Fastify preHandler that reads the `x-telegram-init-data` header, verifies+upserts, attaches `request.telegramInitData`/`request.telegramUser` (declared via `declare module "fastify"` in the same file), and replies 401 without invoking the route handler on any failure (missing header, bad signature, stale auth_date) — this is the piece m1-03's POST /auth/telegram route will wire in to mint the JWT. Added `@postauto/db` as a dependency of `@postauto/api` (package.json) and added `export type * from "@prisma/client";` to packages/db/src/client.ts so the User type is importable from `@postauto/db` (previously only PrismaClient was re-exported). Unit tests (apps/api/src/middleware/telegram-init-data.test.ts, 11 tests) cover: valid signature accepted; tampered payload (mutated field post-signing) rejected; payload signed with a different bot token rejected; auth_date >24h old rejected; auth_date just under 24h old accepted; missing hash field rejected; missing user field rejected; upsertTelegramUser maps fields and calls prisma.user.upsert correctly; and three Fastify-integration cases via app.inject() against a real preHandler-wired route (missing header -> 401, invalid signature -> 401, valid payload -> 200 with upserted user attached to the response). Test fixtures use a hardcoded fixture bot token ("123456:fixture-bot-token-for-tests") with a local `signInitData()` helper that independently reimplements the signing side of the algorithm, so a passing test also cross-validates that the verification implementation matches the documented algorithm rather than just mirroring the same code.
